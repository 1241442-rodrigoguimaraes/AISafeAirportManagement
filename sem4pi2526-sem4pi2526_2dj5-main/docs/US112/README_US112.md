# US112 - Monthly Statistics Report Generation

## 1. Requirements Engineering

### 1.1 User Story

As a Flight Control Operator, I want to generate a monthly statistics report.

The solution must be foundational for future report types, such as compliance or incident reports, while keeping a consistent structure and branding.

### 1.2 Acceptance Criteria

- The operator selects a month and year.
- The system generates a monthly statistics report for the selected period.
- The report aggregates simulation statistics from the selected month.
- The report follows a reusable report generation strategy.
- The report is saved to a file and the output path is shown to the operator.
- Only Flight Control Operators may generate the report.

## 2. Implemented Approach

US112 aggregates the timestamped report files generated by US111:

```text
SCOMP/reports/simulation_report_yyyyMMdd_HHmmss.txt
```

The raw SCOMP file is ignored:

```text
SCOMP/reports/simulation_report.txt
```

The US112 parser is specific to the real US111 format. It reads:

- `Total flights: N`
- flight entries in the format `- Flight <designator> (id: <id>) - <STATUS>`
- safety violations in the `SAFETY VIOLATIONS` section by counting `Violation #N`
- violation `Timestamp:` and Flight A/B positions
- `VALIDATION RESULT: PASS|FAIL`

There is no database persistence in US112. The output is a plain text file:

```text
monthly_statistics_report_yyyy_MM.txt
```

## 3. Design

### 3.1 Strategy Pattern

The report generation mechanism uses the Strategy Pattern:

| Component | Responsibility |
|---|---|
| `ReportGenerator` | Strategy interface for report generators |
| `MonthlyStatisticsReportGenerator` | Concrete strategy for monthly statistics |
| `ReportGeneratorFactory` | Provides the default monthly strategy |
| `GenerateMonthlyReportController` | Authorizes and delegates to the injected strategy |

The controller does not instantiate `MonthlyStatisticsReportGenerator` directly in its business method. Tests inject a fake strategy.

### 3.2 Domain Objects

| Object | Purpose |
|---|---|
| `SimulationReportSnapshot` | Parsed data from one US111 report file |
| `MonthlyStatistics` | Aggregated totals for the selected month |
| `MonthlyReportWarning` | Malformed file skipped during aggregation |
| `MonthlyStatisticsReport` | Full monthly report model |

### 3.3 Aggregation Rules

- `totalSimulations`: number of successfully parsed report files in the month.
- `totalFlights`: sum of all flight entries across reports.
- Duplicate flight rows count as separate simulated executions.
- `totalSafetyViolations`: sum of counted `Violation #` entries.
- `passedSimulations`: reports with `VALIDATION RESULT: PASS`.
- `failedSimulations`: reports with `VALIDATION RESULT: FAIL`.
- Flight status totals are counted exactly as they appear.
- Malformed files are skipped and listed in the report warnings.
- A month with no files still generates a valid report saying no data was found.

## 4. Paths

No hardcoded absolute paths are used.

Input directory resolution:

1. `simulation.reports.input.dir`
2. `scomp.dir/reports`
3. `../SCOMP/reports`

Output directory resolution:

1. `monthly.reports.output.dir`
2. same fallback report directory as above

The Tester and Collaborators apps configure these paths to:

```text
../SCOMP/reports
```

## 5. UI

The feature is available in:

```text
Simulation Reports >
1. Generate Simulation Report
2. Generate Monthly Statistics Report
0. Return
```

The monthly UI asks for:

- year;
- month, validated between `1` and `12`.

## 6. Tests

Tests are placed with package declarations matching the tested classes:

```text
eapli.base/alsafe.core/src/test/domain/simulationreport/
eapli.base/alsafe.core/src/test/controller/simulationreport/
```

Covered scenarios:

- parse the real US111 timestamped report format;
- derive violation count from `Violation #`;
- count duplicate flight rows as separate entries;
- aggregate multiple reports in the same month;
- ignore files from other months;
- generate a no-data monthly report;
- skip malformed files and list warnings;
- authorize only Flight Control Operators;
- inject report strategy into the controller.

Run:

```bash
mvn -pl alsafe.core test
```

## 7. Manual Demonstration

1. Generate one or more US111 reports.
2. Run the Tester app.
3. Log in as:

```text
Username: JoVi@gmail.com

```

4. Open `14. Simulation Reports >`.
5. Select `2. Generate Monthly Statistics Report`.
6. Enter the desired year and month.
7. Confirm that `monthly_statistics_report_yyyy_MM.txt` is created in `SCOMP/reports/`.
