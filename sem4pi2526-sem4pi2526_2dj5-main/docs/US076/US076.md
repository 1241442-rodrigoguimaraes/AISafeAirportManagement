# US076 - List pilot roster

## 1. Context

Air Transport Company Collaborators need to consult the list of pilots that belong to their company. This list is the company pilot roster and will support future operations such as assigning pilots to flight plans.

### 1.1 List of issues

#### Analysis:

1. **What is a pilot roster?**
- The pilot roster is the set of pilots associated with a given Air Transport Company.

2. **Who can list the pilot roster?**
- Only an authenticated Air Transport Company Collaborator can list the roster of their own company.

3. **Should pilots from other companies be visible?**
- No. The ATCC can only list pilots belonging to their own Air Transport Company.

4. **Should inactive pilots be listed?**
- No. The roster should list active pilots. This also prepares the system for US077, where pilots can become inactive.

#### Design:

- Design of the controller `ListPilotRosterController`.
- Design of the DTO `PilotDTO` to present pilot information.
- Design of the UI `ListPilotRosterUI`.
- Design of `ListPilotRosterAction` to expose the use case in the ATCC console app.
- Use of `PilotRepository` to retrieve active pilots by company.
- Use of `CollaboratorRepositoryATCC` to identify the authenticated collaborator's company.

#### Implement:

- UI: `ListPilotRosterUI`
- Action: `ListPilotRosterAction`
- Application: `ListPilotRosterController`
- DTO: `PilotDTO`
- Persistence usage: `PilotRepository`

#### Test:

- Unit tests for `ListPilotRosterController`.
- Manual verification through the ATCC console app.

## 2. Requirements

**US076** - As an Air Transport Company Collaborator, I want to list my company's pilot roster.

**Acceptance Criteria:**

- The operation must only be available to authenticated Air Transport Company Collaborators.
- The system must identify the company of the authenticated ATCC.
- The system must list only pilots belonging to that company.
- The system should not list inactive pilots.
- The listed data should include enough information to identify each pilot and their aircraft model certifications.

**Dependencies/References:**

- US030: Authentication and authorization.
- US060: Air Transport Companies must exist.
- US061: The authenticated ATCC must be associated with an Air Transport Company.
- US075: Pilots must be added before they can appear in the roster.
- US077: Inactive pilots should not appear in the active roster.

## 3. Analysis

The use case is company-scoped. The ATCC does not select the company manually. The system obtains the authenticated user, finds the corresponding `CollaboratorATCC`, and retrieves the associated `AirTransportCompany`.

After identifying the company, the controller queries the `PilotRepository` for active pilots belonging to that company.

The UI displays the resulting roster. If no pilots exist, an informative message is shown.

## 4. Design

The design follows the existing layered architecture:

- **Presentation Layer**: `ListPilotRosterUI` displays the pilots returned by the controller.
- **Application Layer**: `ListPilotRosterController` enforces authorization, identifies the authenticated ATCC's company and retrieves the roster.
- **Domain Layer**: `Pilot` represents each roster entry.
- **Persistence Layer**: `PilotRepository` provides the query to retrieve active pilots by company.

### 4.2 Acceptance Tests

**Unit Test 1: List active company pilots**
- **Action:** Authenticated ATCC requests the pilot roster.
- **Expected Result:** Active pilots from the ATCC's company are returned.

**Unit Test 2: Do not list pilots from another company**
- **Action:** Repository contains pilots from several companies.
- **Expected Result:** Only pilots from the authenticated ATCC's company are returned.

**Unit Test 3: Do not list inactive pilots**
- **Action:** Repository contains active and inactive pilots for the same company.
- **Expected Result:** Only active pilots are returned.

**Manual Test 1: List pilot roster through ATCC app**
- **Action:** Log in as an ATCC and select List Pilot Roster.
- **Expected Result:** The system displays the active pilots from the ATCC's company.

**Manual Test 2: Empty roster**
- **Action:** List the roster for a company without active pilots.
- **Expected Result:** The system displays an informative message.

## 5. Implementation

### Key Classes

1. `ListPilotRosterController`: application controller for listing the company pilot roster.
2. `PilotDTO`: data transfer object used to present pilot information.
3. `ListPilotRosterUI`: console UI for displaying the pilot roster.
4. `ListPilotRosterAction`: menu action to launch the UI.
5. `PilotRepository`: repository used to retrieve active pilots by company.

## 6. Integration/Demonstration

To demonstrate the functionality:

1. Build the project with `mvn test`.
2. Run the ATCC console application.
3. Log in with an Air Transport Company Collaborator.
4. Add one or more pilots using US075, if needed.
5. Select List Pilot Roster.
6. Confirm that only active pilots from the authenticated ATCC's company are displayed.

## 7. Observations

The roster is not planned as a separate aggregate. It is represented by querying the active `Pilot` aggregates associated with an `AirTransportCompany`.
